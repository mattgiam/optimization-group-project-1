Group Project 1 · Image Classification

Teaching a network to read handwritten digits

Five architectures, one dataset, and the difference between 97.7% and 99.5%.

MNIST is 70,000 small grayscale images of handwritten digits, each one a 28×28 grid of pixel intensities. The goal for this project was simple to state and harder to hit: build a network that classifies these digits correctly more than 99% of the time. We got there, then kept going — the final model scores 99.5% on digits it never trained on.

What follows is the path we took to get there: the architectures we tried, what each one told us about what to fix next, and what the model still gets wrong.

Starting simple, adding one idea at a time

Rather than guess at a final architecture, we started with the simplest possible network and changed one thing at a time, judging every attempt on validation accuracy.

Two patterns showed up repeatedly. First, stacking more, smaller convolutional layers helped more than making any single layer bigger. Second, once the network had enough capacity to fit the training set well, controlling overfitting became increasingly important. Dropout and batch normalization helped improve validation performance.

The winning architecture

The best-performing network paired convolutional layers with batch normalization and dropout, allowing the model to extract increasingly complex image features while controlling overfitting.

We checked the flattened output size deliberately — 7×7×64 = 3,136 nodes — before adding the dense layers. Pool too aggressively and the network can discard useful image information before the classifier sees it.

Results on data the model never trained on

Once we selected the winning architecture, the final network was evaluated on the 10,000-image MNIST test set.

99.50% test accuracy
50 / 10,000 digits misclassified

Test accuracy slightly exceeded the best validation accuracy from the tuning phase. That can happen because the final training run uses the full training dataset and because small run-to-run differences are normal at this level of accuracy.

What the model gets wrong

Of 10,000 test digits, 50 were misclassified. Several errors involve digits with very similar handwritten shapes.

Looking through the full confusion matrix makes those patterns clearer:

Mix-up True → predicted Count
4 → 9 digit 4 read as 9 6
9 → 4 digit 9 read as 4 5
5 → 3 digit 5 read as 3 4
7 → 2 digit 7 read as 2 3
7 → 1 digit 7 read as 1 3

The most common mistakes come down to stroke shape. An open-topped 4 and a 9 can look extremely similar, while a quickly written 5 can resemble a 3. Some MNIST examples are genuinely ambiguous even to a human reader at 28×28 resolution.

Will it ever hit 100%?

Probably not. Some MNIST test images are ambiguous or arguably mislabeled. At that point, pushing toward 100% can mean fitting label noise rather than meaningfully improving handwriting recognition.

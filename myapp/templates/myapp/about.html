Group Project 1 · Image Classification

Teaching a network to read handwritten digits

Five architectures, one dataset, and the difference between 97.7% and 99.5%.

MNIST is 70,000 small grayscale images of handwritten digits, each one a 28×28 grid of pixel intensities. The goal for this project was simple to state and harder to hit: build a network that classifies these digits correctly more than 99% of the time. We got there, then kept going — the final model scores 99.5% on digits it never trained on.

What follows is the path we took to get there: the architectures we tried, what each one told us about what to fix next, and what the model still gets wrong.

Starting simple, adding one idea at a time

Rather than guess at a final architecture, we started with the simplest possible network and changed exactly one thing at a time, judging every attempt on validation accuracy (a 20% split held out from training).

Two patterns showed up repeatedly. First, the assignment's tip held up in practice: stacking more, smaller convolutional layers helped more than making any single layer bigger. Second, once the network had enough capacity to fit the training set well, the gap between training and validation accuracy became the thing to watch — dropout and batch normalization each closed that gap in different ways, and batch norm's rocky first epoch (validation accuracy briefly fell to around 28% before recovering) was a reminder that "the first epoch looks broken" isn't always a sign to abandon a change.

The winning architecture

The best-performing network paired every convolution with batch normalization and used two convolutional layers per resolution before pooling, so the network extracts more features at each scale before it throws spatial information away:

We checked the flattened output size deliberately — 7×7×64 = 3,136 nodes — before adding the dense layers. That number matters more than it looks: pool too aggressively and the flatten layer collapses to a few dozen nodes, which means most of the image's information was thrown away before the classifier ever saw it.

Results on data the model never trained on

Validation accuracy tells you how a model tunes; it doesn't tell you how it generalizes. Once we picked the winning architecture, we rebuilt it and trained it once more on the full 60,000-image training set, then scored it, once, on the 10,000-image test set it had never seen in any form.

99.5% test accuracy
50 / 10000 digits misclassified

Test accuracy (99.5%) actually edged out the best validation accuracy (99.39%) from the tuning phase. That is not a sign the model generalizes unusually well — it is mostly what happens when a network's final training run uses all 60,000 images instead of the 80% it saw during tuning, plus ordinary run-to-run noise at this level of accuracy. On a dataset this size, a few extra correct digits move the percentage by hundredths of a point.

What the model gets wrong

Of 10,000 test digits, 50 were misclassified. Here are 15 of them, labeled with what they actually were and what the network guessed instead:

Looking through the full confusion matrix makes the pattern clearer than any individual example:

Mix-upTrue → predictedCount
4 → 9digit 4 read as 96
9 → 4digit 9 read as 45
5 → 3digit 5 read as 34
7 → 2digit 7 read as 23
7 → 1digit 7 read as 13

The two dominant confusions — 4 read as 9, and 5 read as 3 — both come down to stroke shape rather than anything the network failed to learn. An open-topped 4 and a 9 differ mainly by whether the top loop closes; a hastily written 5 and a 3 differ by whether the middle stroke curves all the way around. Several of the 50 misclassified images look genuinely ambiguous even to a human reading them at 28×28 resolution — some are arguably mislabeled in the dataset itself.

Will it ever hit 100%?

Realistically, no. MNIST's test set contains a small number of images that are ambiguous or, by most people's reading, mislabeled. A model that scored 100% on this exact test set would be fitting that label noise, not learning to read digits better. Published results on MNIST plateau around 99.7–99.8% for exactly this reason, which puts our 99.5% in a reasonable, non-overfit range for a project-scale model rather than a heavily-tuned research pipeline.
